# Turn technical content into visible objects and mechanisms

The intended figure combines **semantic framing, recognizable icons, and mechanism illustrations**. Labels name those objects and actions. A box-and-arrow outline can help plan the flow, but it does not by itself satisfy a request for an illustrated research architecture.

## Give each visual form a job

| Form | What it communicates | Useful treatment |
| --- | --- | --- |
| Frame and connector | Scope, ownership, sequence, dependency | Enclosing regions and precise routes; avoid outlining every phrase |
| Object icon | What an entity is | A recognizable agent, document, code sheet, tool, storage object or output symbol |
| Structural illustration | What is inside an object | A tree, graph, matrix, record, sequence, buffer or other source-supported structure |
| Mechanism illustration | How an operation changes or uses objects | Before/after states, a highlighted path, a selected subset, split/merge, read/write or another visible action |
| Short label | The exact name or local meaning | Readable text attached to its object; interface names and necessary example text remain explicit |

Icons and mechanism illustrations have different jobs. A document icon identifies a document; highlighted lines becoming chunk records explain segmentation. A tree symbol identifies a hierarchy; visibly changed nodes or edges explain a structural operation. A small icon in the corner of an otherwise text-only process box does not illustrate the process.

## Plan the visual encoding before placing boxes

After establishing the technical story, map its important content to a compact visual plan:

`entity or operation → visible object/structure → meaningful state or change → short label`

Choose recognizable icons for the important actors and artifacts. For the central operation, identify the actual structure it reads or changes and what the reader should see happen. Carry an example object through related stages using consistent identity, shape and color. Use schematic values only as declared illustrations; do not invent scientific behavior to make the figure busier.

Allocate space around those drawings before enclosing regions. Let the mechanism determine panel proportions and internal composition. A region showing an object collection, one showing a transformation and one showing a result need not share the same stack of rectangular cards. Preserve alignment and coherent spacing without making all stages geometrically identical.

## Worked visual choices: document retrieval

This document-retrieval example illustrates concrete visual choices. They are reusable drawing techniques, not a template to copy into unrelated domains.

| Concept | What to draw | What the drawing explains |
| --- | --- | --- |
| Source documents | Offset pages with distinct identifiers and a selected text span | Multiple concrete sources and the location of relevant content |
| Segment text | The source span beside separated, labeled chunk strips | A document becomes smaller addressable objects |
| Encode chunks | Chunk identifiers aligned with rows of vector cells | Each chunk has an associated representation |
| Searchable index | Aligned record fields containing chunk identity, vector and source span | What is stored and which fields stay linked |
| Retrieve evidence | A query object and ordered result records with a selected record | Ranking and selection, using schematic bars rather than invented measurements |
| Carry a citation | The same source identity/span in an evidence record and an answer citation | How the output retains a connection to the source |

The drawn records, cells, strips and spans carry information. Header bands, rounded corners and accent colors organize them. Keep this distinction when adapting to another project.

## Make the result expressive and precise

- Use enough meaningful icons to make the major object types visually recognizable. Keep one flat line style, compatible stroke weights and restrained accents; there is no icon-count target.
- Give the important mechanism a genuine local illustration with discernible objects, relationships or changes. Keep supporting stages compact when expansion would add no information.
- Use varied internal arrangements justified by content: an object cluster, a matrix, a horizontal transformation, a graph, or a record view. Reuse the same shape for the same object, not for every concept.
- Keep the main story visible at the intended viewing size. Enlarge a meaningful object or reorganize its region before reducing label size.
- Preserve editable vector icons, text and diagram geometry for PowerPoint. Standalone figures and presentation slides use the same visual grammar; only presentation pages default to left diagram plus right takeaways.

## Review for visible mechanism

Look at the drawing before reading every label: which actors and artifacts are recognizable, and where is the central structure or transformation visible? If the core is still mainly sentences inside repeated boxes, return to the visual plan and illustrate that mechanism. Adding more boxes, a few decorative icons or more color will not resolve the missing representation.

Compare the reference's object types, internal drawings and spatial hierarchy, as well as its palette. Check the actual rendered result for both expressive content and precise connections. Fix observed shortcomings and finish when the requested figure is satisfied; no iteration or finding quota applies.
